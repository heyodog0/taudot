# clients/render/fonts: TeX's fonts without MuPDF (Phase B, step 4)

**Status: paused 2026-11-03, not wired in and not tested yet.** API agreed between the renderer's engine and
interpreter work.

- `taudot_font.h` / `taudot_font.c`: the `tf_` API. FreeType loads fonts; MuPDF 1.28's answers are matched by
  behaviour (read in its source, not copied): names, ascent and descent, encode (by code, by glyph name with fallbacks),
  advances, outlines at 65536 units/em with fz_path's degenerate-segment rules, glyph names, glyph text.
- `glyphlists.c`: glyph name → Unicode from the Adobe Glyph List (Apache-2.0) and texglyphlist.txt (lcdf-typetools),
  both read at run time from the TeX bundle via `tf_glyph_lists()`, so neither is compiled in.
- `tables.h`: CP437 and the TrueType standard order → Unicode, generated by `gen_tables.py`.
- `tests/collect.py`: the reference (dlist lists plus the font bytes, from a scratch txp-render that dumps them).
- `tests/compare.c`: tf_ against MuPDF on every collected font. Written, not yet built or run.

Both .c files compile cleanly: `cc -Wall -Wextra -c taudot_font.c glyphlists.c $(pkg-config --cflags freetype2)`.
